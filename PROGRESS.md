## Відкрите

### G. Джерело контенту — головне вузьке місце

Генерація тексту не почата свідомо: в акаунті лише два пости, для наслідування
стилю замало. Потрібно, у `content/knowledge/`:

- 5–10 реальних постів, краще з каналу з історією
- транскрипти демо і дзвінків з клієнтами — звідти беруться слова, якими
  клієнти самі описують свої проблеми
- опис продукту: що Casy робить, скільки коштує, чого свідомо не робить

### I. Tech Provider verification

Не потрібно, поки працюємо на власному акаунті. Знадобиться лише для доступу до
чужих Threads-акаунтів: окрема верифікація ~тиждень плюс App Review на кожен
дозвіл.

### Розгортання

Рішення: **на Pi їде тільки застосунок**, legal-сторінки лишаються на GitHub
Pages за адресою `rayofgoodness.github.io/threads-agent/`. Meta вимагає їх
доступними постійно, а домашній Pi вимикається — тоді privacy й data-deletion
віддавали б 502.

Дашборд буде на `https://threads.quarters.casa` через Cloudflare Tunnel —
піддомен уже наявного на малині тунелю, який поруч тримає `observer.`,
`grafana.` і `mcp.`. Встановлення — `sudo bash deploy/install.sh` на самій
малині, решта в `deploy/README.md`.

Перенесення legal на піддомен описане runbook'ом у `deploy/README.md`, але
відкладене — і потребує іншого імені, бо `threads.` тепер зайнятий дашбордом. Порядок там не довільний: GitHub вмикає 301 на власний домен
одразу, тож домен, заданий раніше за DNS-запис, кладе саме ті URL, що
зареєстровані в Meta. Перевірено на практиці 19 серпня.

### Дрібніше

- Черга не публікується сама — потрібен cron або launchd на `agent.ts run --yes`
- `refresh_access_token` треба викликати до 18 жовтня, інакше повна авторизація
  заново
- Медіа-пости (IMAGE, VIDEO, CAROUSEL) реалізовані в клієнті, але на живому
  акаунті не перевірені — тільки TEXT

## Нотатки з процесу

Те, що коштувало часу і не очевидне з коду:

- **Токен беруть у User Token Generator** (Use Case → Access the Threads API →
  Settings), а не через OAuth-URL. Authorize віддає `error_code: 1`, а отриманий
  ним код несе дозволи на момент **первинної** авторизації акаунта — додані
  пізніше в токен не потрапляють, скільки не переавторизовуйся.
- `issued_at` у `debug_token` — час первинної авторизації, а не видачі токена.
  Однаковий `issued_at` не доводить, що токен той самий.
- **Threads App ID ≠ Meta App ID.** У `.env` перший (`1860340038261236`), у
  дашборді видно другий (`1794866701670684`).
- Redirect/Callback URLs — всередині Use Case, не в загальних App Settings.
- Видалення вимагає `threads_delete`, і відмова прилітає **після** того, як пост
  став публічним.
- `/me/threads` відстає від записів на кілька секунд.
- `/me/replies` — це відповіді, **написані** акаунтом, а не адресовані йому.
  Вхідні читаються обходом власних постів.
- Node type stripping не компілює: parameter properties, `enum` і `namespace`
  падають при запуску, хоча `tsc` їх пропускає.
- `dev.meta.ai` — окремий geo-заблокований продукт, не плутати з
  `developers.facebook.com`.
- **Ніколи не вставляти access token чи app secret у чат або git** — лише `.env`,
  який у `.gitignore`.
